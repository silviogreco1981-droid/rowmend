# RowMend 0.8 acquisition cycle

## Goal

Validate RowMend 0.8 with relevant external users before committing fully to RowMend 0.9.

Primary funnel:

`visit → project_created → workflow_file_loaded → workflow_run_completed → workflow_output_exported`

The strongest signal is not raw traffic. It is whether relevant users create a project, run a workflow and export an output.

## Product positioning

**Build and run repeatable data workflows locally. No signup. No upload.**

Supporting angles:

- recurring vendor/customer CSV and Excel files;
- cleanup recipes instead of one-off spreadsheet edits;
- data contracts for schema drift;
- import validation and SQL preparation;
- source-to-target migration reconciliation;
- local-first processing for sensitive data;
- powerful browser-side functionality without artificial row paywalls.

## Measurement

Review by `acq_source` where available.

Metrics:

- visits;
- project_created;
- workflow_file_loaded;
- workflow_run_completed;
- workflow_output_exported.

Ratios:

- Project creation rate = project_created / visits
- File-load rate = workflow_file_loaded / project_created
- Completion rate = workflow_run_completed / workflow_file_loaded
- Export rate = workflow_output_exported / workflow_run_completed

## Interpretation

Examples:

- 100 visits, 0 projects → positioning or project UX problem.
- projects created, few file loads → trust or onboarding problem.
- files loaded, few completed runs → runner friction or bugs.
- runs completed, few exports → result/output value may be unclear.
- a small number of relevant users completing and exporting workflows → meaningful signal.

## 0.9 gate

Current 0.9 target: **Run Insights & Data Drift**.

Prioritize implementation after either:

1. external users are completing Workflow Runner runs; or
2. qualitative feedback repeatedly asks for historical/drift visibility.

Do not use a production deploy solely for acquisition copy, minor analytics changes or a single guide while Netlify deploys are constrained. Accumulate such changes into the next substantial release candidate.
